- **Conversion presets**: save a target format and resize settings under a name, such as "Blog" for WebP images 300 px wide, and pick it from the new **Convert > Presets** submenu instead of setting everything by hand ([#23](https://github.com/Oire/sic/issues/23)). Choosing a preset fills in the format and resize controls without converting, and its sizes stay put while you add and select images. **Manage Presets** edits and removes them. A preset whose format is hidden in Settings still applies, and that format stays in the dropdown until SIC! closes.
- **`--preset` on the command line**: `sic -i photo.png --preset Blog` converts with a saved preset. An explicit `--output` extension, `--format`, `--resize` or `--crop` wins over the matching part of the preset, and an unknown name fails with the list of saved presets.
- **Native menus and image list**: the menu bar and the image list are now real Windows controls rather than WinForms-drawn imitations, which is what screen readers need from them ([#68](https://github.com/Oire/sic/issues/68)). The menu is a genuine `HMENU`, announced as a menu bar with real submenus; the image list is a genuine `SysListView32`, so a screen reader reads every column instead of only the file name. Nothing changes about how either looks or behaves for sighted users.
- **Smaller icons**: the 256 px image in an ICO file is now stored as PNG, as in Windows' own icons, instead of as an uncompressed bitmap. A multi-size icon made with the Windows application preset drops from about 285 KB to about 85 KB, with the same pixels.
- **Signed by Oire Software**: the installer, its uninstaller and `sic.exe` now carry Oire Software's digital signature ([#86](https://github.com/Oire/sic/issues/86)). When you install, Windows' permission prompt names Oire Software as the verified publisher instead of an unknown one. Windows SmartScreen may still warn for a while after a release; the manual's Installation section explains what to check.
- **Settings in JSON**: settings are now stored in `sic.json` instead of `Sic.cfg` ([#89](https://github.com/Oire/sic/issues/89)). The first start moves your settings over automatically and keeps the old file as `Sic.cfg.bak`. A value SIC! can't use is reset on its own, keeping every other setting, and a damaged file is kept as `sic.json.bad` and reported rather than silently replaced.
- **One window at a time**: starting SIC! while it's already running brings the open window forward, or the dialog open in it, instead of opening a second one. If Windows doesn't let it come forward, SIC! says it's already running and that Alt+Tab switches to it. Portable copies in different folders, or a portable and an installed copy, still run side by side, and the command line still runs while the window is open.
- Menu shortcut labels now use the key names of your language, such as `Strg+N` in German or `Maj` in French, matching the manual. The keys themselves are unchanged.
- The **Edit** and **Convert** menus are no longer unavailable as a whole while the queue is empty; their items that need images are unavailable on their own.
- A mistyped size in the main window now gets its own message and moves the focus to that field.
- The main window now shows the SIC! icon in its title bar and in Alt+Tab instead of the generic Windows Forms one.
- SIC! can now be installed and updated through WinGet
- Converting an image with one side of 256 px or more and the other smaller, such as 300x200, to ICO now stores it as PNG with the right dimensions. It used to come out as an uncompressed bitmap of about 250 KB with the wrong width recorded in the file.
- Icons added by link, such as a site's `favicon.ico`, are now accepted. SIC! used to reject them as not an image, although it opened the same icon from a file.
- Converting an image larger than 512 px to ICO now fails with a clear message about the 512x512 px limit instead of an internal error, and every size of a multi-size icon is checked, not only the first.
- A language set to a code SIC! has no translation for, such as `pl`, now falls back to English as intended.
- Command line: converting a link with `--format` names the output after the file in the link, or `downloaded_image` when the link has no file name, instead of writing a file called `.jpg`.
- A downloaded image's file name no longer keeps characters a file name can't hold, so an escaped slash in a link can't place the converted file outside the output folder.
- Command line: when SIC! can't save its settings, it now says so in the console instead of opening a message box.
- A language setting SIC! doesn't recognize no longer stops it from starting: it falls back to the system language.
- A portable copy moved to another folder or drive letter now keeps saving to its own `Converted` folder.
- Command line: when the custom output folder is missing, for instance on an unplugged drive, SIC! uses the default folder for that run only and no longer forgets the custom one.
- Command line: `--resize` now rejects sizes above 65535 pixels, as the main window does, and an unsupported `--format` no longer creates the output folder.
- The size SIC! fills in for the other side of a very wide or very tall image is now always from 1 to 65535 pixels; it could be 0 before.
- SIC! now has automated tests, run on every change: conversion, resizing, ICO output, fit to file size, the command line and the translation catalogs ([#88](https://github.com/Oire/sic/issues/88)).
